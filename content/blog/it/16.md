## TypeScript 7 è realtà, Node.js 27 apre l'alpha e Claude si allarga tra agent e skill aperte

*Toolchain più veloci, standard più aperti, modelli abbastanza piccoli da usare ovunque. Ottobre 2026 ha spinto la stessa idea su tre fronti contemporaneamente, e ognuno cambia il modo in cui scriveremo e rilasceremo codice nei prossimi mesi.*

Ogni tanto mi fermo a guardare cosa è cambiato negli strumenti che uso tutti i giorni. Questa volta il quadro è insolitamente coerente: TypeScript ha un compilatore nativo, Node.js ha ripensato il modo in cui rilascia le versioni, e Anthropic punta su modelli piccoli e formati aperti per gli agenti. Ecco cosa è successo, cosa ne penso e cosa farei.

Una nota di metodo: ho verificato queste notizie sulle fonti primarie ogni volta che potevo. Quando un'informazione arriva da una sola fonte secondaria, lo dico esplicitamente.

## TypeScript 7: il compilatore diventa nativo

TypeScript 7.0 è uscito l'8 luglio 2026 ed è la prima major in cui il compilatore non gira più su Node.js: è un eseguibile nativo, portato in Go. Secondo gihyo.jp, parsing, type checking ed emissione ora avvengono in parallelo su memoria condivisa, e nel benchmark citato il build di VS Code risulta **11,9 volte più veloce** rispetto alla 6.0.

È un singolo benchmark, non una promessa valida per ogni codebase. Ma chiunque abbia aspettato `tsc` in un monorepo grande sa quanto conti un numero del genere.

Per il lavoro quotidiano, la novità che mi interessa di più è il supporto ufficiale al **Language Server Protocol**: qualsiasi editor compatibile può ora parlare con il nuovo compilatore. Le API programmatiche native non sono ancora stabili e sono attese nella 7.1. Per questo tool come typescript-eslint possono restare sulla API 6.0 mentre `tsc` passa alla 7.0.

Il percorso di migrazione è piacevolmente semplice:

```bash
# Installazione standard: il compilatore è sempre su npm
npm install -D typescript

# Se un tool importa "typescript" come peer dependency e non è ancora pronto,
# l'alias fornisce la API 6.0 mantenendo il resto sulla 7.0
npm install -D typescript@npm:@typescript/typescript6
```

Il punto delicato è che le opzioni deprecate nella 6.0 ora sono state rimosse. La mia fonte non le elenca, quindi prima di aggiornare conviene leggere le note di release ufficiali e far girare `tsc` in CI su un branch separato.

## React 19.3: le View Transitions diventano dichiarative

React 19.3 è uscito il 9 settembre 2026. Il blog ufficiale elenca **View Transitions**, **Fragment Refs**, una nuova funzione `browser()` e il supporto ai **Trusted Types**. Prima di scrivere di API specifiche voglio approfondire i dettagli, ma una funzionalità spicca già.

Dal punto di vista UI/UX, le View Transitions sono la vera notizia. Portano le transizioni native del browser dentro il modello dichiarativo di React, quindi i cambi di pagina che prima richiedevano una libreria di animazione possono appoggiarsi alla piattaforma.

Attorno a React, i numeri di ottobre di This Week in React mostrano movimento costante su Next.js, TanStack Start, React Aria, Base UI e React Router. Sono titoli, non changelog, ma è chiaro che l'ecosistema non ha rallentato.

## Node.js: un ottobre denso e un nuovo modello di rilascio

Ottobre è stato un mese pieno per Node.js:

- **21 ottobre**: rilasci di sicurezza 22.23.4, 24.22.1 (LTS) e 26.12.1 (Current). Ne parlo nella sezione sulla sicurezza più avanti.
- **28 ottobre**: Node 26.13.0 (LTS) e 24.22.2 (LTS).
- **29 ottobre**: la prima alpha di Node.js 27.

La notizia più grande però è strutturale. Secondo il post del progetto "Evolving the Node.js Release Schedule", ripreso da ecorpit, **ogni major diventa LTS** e la vecchia distinzione tra versioni pari e dispari scompare. Node 27 dovrebbe avere circa trenta mesi di supporto: Current ad aprile 2027, LTS a ottobre 2027.

Per i team questo semplifica la scelta delle versioni. Significa anche che conviene tenere d'occhio il file `schedule.json` nel repository Release di Node.js, che il progetto indica come riferimento, perché le date non sono ancora definitive.

## Sicurezza: un mese da patchare, non da rimandare

Se di questo articolo metti in pratica una sola sezione, che sia questa. Ottobre ha portato due rilasci di sicurezza che colpiscono il cuore di uno stack JavaScript tipico.

### Next.js e React: due RCE critiche (14 ottobre)

Next.js ha pubblicato un aggiornamento fuori calendario, **16.4.1** e **15.5.28**, che corregge tre vulnerabilità, due delle quali con advisory collegati in React:

- **RCE in `use cache` (Critical, GHSA-673q-mjm6-r5xr)**: nelle app App Router con Cache Components, una funzione `use cache` che restituisce più typed array può portare a esecuzione di codice remoto senza autenticazione. Non esiste un workaround, e il team di Next.js consiglia di aggiornare anche se il tuo codice non ha funzioni di questo tipo.
- **RCE nella Image Optimization tramite SVG (Critical, CVE-2026-96889)**: un bug di memoria in una libreria usata da `sharp` permette l'esecuzione di codice quando Next.js gira su Linux basato su glibc. Il workaround è assicurarsi che Next.js usi `sharp` **0.35.5 o successivo**.
- **Denial of Service nelle Server Actions (High, GHSA-p3m5-59mp-jv5r)**: richieste costruite ad arte possono far salire l'uso di CPU fino a bloccare il processo. Sono colpite solo le app App Router con almeno una Server Action.

Quello che mi colpisce è dove stanno i bug: non nel codice applicativo, ma in funzionalità che molti di noi hanno adottato proprio perché il framework prometteva di gestire le parti difficili, come cache, elaborazione delle immagini e mutazioni lato server. Più il framework fa per noi, più la sua cadenza di patch diventa parte della nostra.

```bash
npm install next@16.4.1   # 16.4
npm install next@15.5.28  # 15.5
npm ls sharp              # verifica che sharp sia >= 0.35.5
```

Un dettaglio pratico dalle note di Netlify: le deploy preview pubbliche e i branch deploy restano vulnerabili finché non li elimini, anche dopo aver patchato `main`.

### Node.js: dieci CVE e un bug di Brotli sfruttato attivamente (21 ottobre)

Il rilascio di sicurezza di Node.js ha corretto dieci CVE sulle linee 22.x, 24.x e 26.x, con le fix in **22.23.4**, **24.22.1** e **26.12.1**. Il più importante è **CVE-2026-111497**: una scrittura fuori dai limiti nel decoder Brotli incluso in Node.js. Un input compresso malformato può far crashare il processo, esporre memoria o potenzialmente portare a esecuzione di codice remoto, se la tua app decomprime dati Brotli non fidati con `node:zlib`.

Node.js lo classifica High, mentre Google gli assegna Critical (CVSS v4 9.2). Secondo Rapid7, il 27 ottobre la CISA lo ha aggiunto al suo catalogo delle vulnerabilità sfruttate attivamente. Il bug è nella libreria Brotli di Google, quindi colpisce anche Bun, pacchetti Python, .NET, Envoy e altri: aggiornare solo Node potrebbe non bastare.

Il resto del rilascio è una lezione utile su quanto sia fragile la validazione di rete. Diversi CVE riguardano controlli dei certificati TLS ingannati da scritture insolite degli IP (cifre fullwidth, ottale come `0127.0.0.1`), e alcuni sono fix incomplete di CVE precedenti. Un altro è da conoscere per chi distribuisce eseguibili singoli: `crypto.randomUUID()` e `randomInt()` potevano ripetere gli stessi valori nei processi avviati da snapshot o SEA.

## Claude: modelli piccoli, skill aperte

Il 7 ottobre Anthropic ha annunciato **Claude Haiku 5.5**, il suo modello piccolo più capace finora, pensato per riassunti, subagent e uso del browser. L'annuncio che ho letto non riporta prezzi né finestra di contesto, quindi non tiro a indovinare.

Perché è importante? Nelle pipeline agentiche la parte costosa raramente è l'unica chiamata "intelligente": sono le decine di chiamate piccole che le stanno intorno. Un modello piccolo, veloce e capace rende sostenibile far girare molti subagent in parallelo.

Il 22 ottobre Anthropic ha fatto una mossa che trovo ancora più interessante: ha donato gli **Agent Skills** all'Agentic AI Foundation, parte della Linux Foundation, compresi nome, logo e dominio agentskills.io. Secondo l'annuncio, oltre settanta piattaforme di agenti supportano già lo standard. Mi ricorda quello che i formati di configurazione condivisi hanno fatto per il tooling JavaScript: quando una convenzione non appartiene più a un solo vendor, tutti possono costruirci sopra.

Altre due notizie restano da confermare: Claude Code Review sarebbe arrivato in disponibilità generale per Team ed Enterprise, e Claude Security sarebbe entrato in beta. Entrambe vengono da una sola fonte secondaria, senza link a un annuncio ufficiale, quindi prendetele con cautela. Sul fronte business, il 26 ottobre Anthropic ha depositato l'S-1 per la quotazione in borsa.

## Web Platform e Tailwind: un mese più tranquillo

Sul fronte Web Platform non ho trovato note di rilascio di Chrome o Firefox di ottobre che potessi verificare. Funzionalità come `text-justify`, `shape()`, la HTML Sanitizer API e le animazioni CSS legate allo scroll circolano dagli articoli di febbraio e dalle beta di Chrome 146 e Firefox 149, quindi non sono davvero novità di ottobre.

Tailwind CSS 4.3 risulta uscito, con lo styling delle scrollbar e nuovi colori secondo il feed del blog ufficiale. Non ho ancora trovato una data verificata né il changelog completo. La tendenza generale è però quella che trovo interessante: il CSS nativo continua a prendersi compiti che prima richiedevano librerie, la stessa storia delle View Transitions e di `shape()`.

## Cosa farei questa settimana

- **Usi Next.js?** Aggiorna oggi a 16.4.1 o 15.5.28, verifica che `sharp` sia almeno 0.35.5 ed elimina le vecchie preview pubbliche.
- **TypeScript in un progetto grande?** Prova la 7.0 su un branch, misura i tempi di build e tieni pronto l'alias verso la 6.0 per i tool non ancora aggiornati.
- **Node in produzione?** Passa subito a 22.23.4, 24.22.1 o 26.12.1 (il bug di Brotli è sfruttato attivamente), controlla gli altri runtime che includono Brotli e inizia a pianificare la nuova cadenza annuale delle LTS.
- **Costruisci agenti con Claude?** Haiku 5.5 è un ottimo candidato per i subagent economici, e gli Agent Skills, ora sotto una fondazione aperta, sono un formato sicuro da adottare se non vuoi legarti a una sola piattaforma.

Il filo comune è facile da vedere: compilatori più veloci, standard che si aprono e modelli abbastanza piccoli da usare ovunque. Molti di questi cambiamenti non faranno notizia da soli, ma tutti cambieranno il modo in cui lavoreremo nel 2027.
