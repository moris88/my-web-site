## Software built by people or with artificial intelligence: what really changes in the code

With artificial intelligence, writing code seems to have become easy. You just describe what you want, and within minutes a working program appears. But "it works today" and "it can be changed tomorrow" are two different things. To understand the difference, I compared two ways of building the same kind of tool: a module for preparing quotes with prices, margins and documents, written by developers, and a tool with the same purpose, written almost entirely with artificial intelligence.

You don't need a technical background to follow along. All you need to know is that a well-organized program is easier to change without breaking something else. What follows measures exactly that: structure, security and ease of maintenance. The data comes from my personal experience: these are observations made while working on both codebases, not an independent study.

## Amount of useful work

The code that makes the program work is of similar size in both cases. The tool written with artificial intelligence, however, carries a large number of lines that only define its visual appearance. The module written by developers also uses styling, but proportionally much less, and its actual logic remains the main part of the work.

There is also a fundamental difference in how the code is written. In most cases, the code written with artificial intelligence is HTML, CSS and vanilla JavaScript, meaning no frameworks or libraries. The module written by developers instead uses established frameworks and libraries, which bring conventions, tools and ready-made checks with them.

In short, the amount of useful work is similar. What changes is how it is organized.

## Structure: small files versus huge files

Think of a filing cabinet. If each folder holds only a few sheets, you find what you need right away. If a single folder holds everything, every search becomes slow and every change risks moving something that was needed elsewhere. The same happens in code.

In the module written by developers, the vast majority of files are small. In the tool written with artificial intelligence, the share of small files is much lower, and a single huge file contains almost all of the screen's logic. Anyone who needs to change that part has to read and understand far more code than necessary.

## Security and readability

Some choices in the code can open the door to problems, for example when text entered by a user ends up directly on the page without any checks. A larger project naturally has more of them, so the number should be compared with the size of the code.

Readability matters too. Lines that are too long are hard to review, and in the tool written with artificial intelligence they are much more frequent.

## Automated checks: stopping errors before they get through

The module written by developers is connected to a series of checks that the computer runs on its own: code style, data type checking, verification before saving, scanning for passwords left in the code, checking external libraries, verification in a test environment before going live, detection of duplicated code blocks and validation of version names. If any of these fails, the change does not go through.

The tool written with artificial intelligence has none of these checks. Errors only surface when someone runs into them while using the program.

## Pace of work and external components

Every project uses components built by others, and each one needs to be updated over time, otherwise it becomes a weak point. The expert module uses several for running the application and just as many for development. The AI tool uses only a few, and almost none for development.

The expert module has a long change history with a steady pace. The AI tool is much younger, so it is not yet possible to see its long-term pace.

## Time spent on new features

I work directly on a client's code, and when a feature needs to be added to the code written by artificial intelligence, it takes me longer. The reason is that the code is disorganized: before changing a single line, you have to figure out where responsibilities lie, and a change often touches places far apart from each other.

## Tests: how we verify that it works

Tests are checks written by developers: every time the program changes, they verify that the main features keep working. The expert module has a test suite that runs automatically on every change. The AI tool has none.

## Pros and cons for developers

Expert development delivers clean, readable code, checks that stop errors before they reach the client, and tracked changes. It is easier to hand the work over to another developer. The downside is time: it requires human effort, has more components to keep updated, and the upfront cost is higher.

Development with artificial intelligence starts quickly and lets you try out an idea in a few hours. But changes require understanding disorganized code, so the time needed grows, and there are no checks to stop errors.

## Pros and cons for clients

With expert development, quality is guaranteed by a process, not just by a demo, and long-term costs are more predictable. The program can be handed over to another team without surprises. The initial cost is higher and timelines are longer.

With artificial intelligence, the initial cost is low and the first versions arrive right away. But every future change costs more, because you have to understand code that no check has verified, and security issues are more frequent.

## Conclusion

Sooner or later, a client building an important tool will need an experienced developer to review, fix and optimize the code. It is the natural next step when a project grows large and has to stand the test of time.

The more the code grows, the harder it becomes for artificial intelligence to keep track of the whole context: the parts already written, the changes already made and those still to come. Every new request risks touching something nobody has in mind anymore.

This leads to a few practical recommendations:

- for modules the client will use for years, expert development remains the right path;
- artificial intelligence is useful for trying out ideas quickly, but its output must pass the same checks as any hand-written code;
- no generated code should go live without a review by a person, and files should be kept small;
- the client should be told the real cost over time, not just the upfront cost.
