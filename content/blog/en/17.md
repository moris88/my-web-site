## TypeScript 7 is here, Node.js 27 opens its alpha, and Claude expands across agents and open skills

*Faster toolchains, more open standards, smaller models built to run at scale. October 2026 pushed the same idea forward on three fronts at once, and each one affects how we'll write and ship code over the next few months.*

Every few months I look back at what changed in the tools I use every day. This time the picture is unusually consistent. TypeScript now has a native compiler, Node.js has rethought how it ships releases, and Anthropic is betting on small models and open formats for agents. Here is what happened, what I think it means, and what I'd do about it.

A note on method: I checked these stories against primary sources wherever I could. When something comes from a single secondary source, I say so.

## TypeScript 7: the compiler goes native

TypeScript 7.0 shipped on July 8, 2026, and it's the first major version where the compiler no longer runs on Node.js. It's a native executable, ported to Go. According to gihyo.jp, parsing, type checking and emit now run in parallel over shared memory, and in the benchmark they cite, the VS Code build is **11.9 times faster** than with 6.0.

That's one benchmark, not a promise for every codebase. Still, anyone who has waited on `tsc` in a large monorepo knows how much that number matters.

For day-to-day work, the change I care most about is official support for the **Language Server Protocol**: any compatible editor can now talk to the new compiler. The native programmatic API isn't stable yet and is expected in 7.1. That's why tools like typescript-eslint can stay on the 6.0 API while `tsc` moves to 7.0.

The migration path is pleasantly simple:

```bash
# Standard install: the compiler is still on npm
npm install -D typescript

# If a tool imports "typescript" as a peer dependency and isn't ready yet,
# the alias provides the 6.0 API while keeping everything else on 7.0
npm install -D typescript@npm:@typescript/typescript6
```

The catch is that options deprecated in 6.0 are now gone. My source doesn't list them, so read the official release notes first and run `tsc` in CI on a separate branch before you switch.

## React 19.3: View Transitions go declarative

React 19.3 came out on September 9, 2026. The official blog lists **View Transitions**, **Fragment Refs**, a new `browser()` function and **Trusted Types** support. I'll wait until I've worked through the details before writing about specific APIs, but one feature already stands out.

From a UI/UX point of view, View Transitions are the headline. They bring the browser's native transitions into React's declarative model, so page changes that used to need an animation library can rely on the platform instead.

Around React, the October issues of This Week in React show steady movement in Next.js, TanStack Start, React Aria, Base UI and React Router. Those are headlines, not changelogs, but the ecosystem clearly hasn't slowed down.

## Node.js: a busy October and a new release model

October was a dense month for Node.js:

- **October 21**: security releases 22.23.4, 24.22.1 (LTS) and 26.12.1 (Current). More on these in the security section below.
- **October 28**: Node 26.13.0 (LTS) and 24.22.2 (LTS).
- **October 29**: the first alpha of Node.js 27.

The bigger story is structural. According to the project's post "Evolving the Node.js Release Schedule", as reported by ecorpit, **every major release now becomes LTS**, and the old even/odd split is gone. Node 27 should get about thirty months of support: Current in April 2027, LTS in October 2027.

This makes version choices simpler for teams. It also means you should watch the `schedule.json` file in the Node.js Release repository, which the project names as the reference, because the dates aren't final yet.

## Security: a month to patch, not to postpone

If you only act on one section of this article, make it this one. October brought two security releases that hit the core of a typical JavaScript stack.

### Next.js and React: two critical RCEs (October 14)

Next.js shipped an out-of-band update, **16.4.1** and **15.5.28**, fixing three vulnerabilities, two of them with upstream advisories in React:

- **RCE in `use cache` (Critical, GHSA-673q-mjm6-r5xr)**: in App Router apps with Cache Components, a `use cache` function that returns multiple typed arrays can lead to unauthenticated remote code execution. There is no workaround, and the Next.js team recommends upgrading even if your code has no such functions.
- **RCE in Image Optimization via SVG (Critical, CVE-2026-96889)**: a memory bug in an upstream library used by `sharp` allows code execution when Next.js runs on glibc-based Linux. The workaround is to make sure Next.js uses `sharp` **0.35.5 or later**.
- **Denial of Service in Server Actions (High, GHSA-p3m5-59mp-jv5r)**: crafted requests can push CPU usage high enough to block the process. Only App Router apps with at least one Server Action are affected.

What strikes me here is where the bugs live: not in application code, but in features many of us adopted precisely because the framework promised to handle the hard parts, like caching, image processing and server mutations. The more the framework does for us, the more its patch cadence becomes part of our own.

```bash
npm install next@16.4.1   # 16.4
npm install next@15.5.28  # 15.5
npm ls sharp              # check that sharp is >= 0.35.5
```

One practical detail from Netlify's notes: public deploy previews and branch deploys stay vulnerable until you delete them, even after you patch `main`.

### Node.js: ten CVEs and a Brotli bug exploited in the wild (October 21)

The Node.js security release fixed ten CVEs across the 22.x, 24.x and 26.x lines, with fixes in **22.23.4**, **24.22.1** and **26.12.1**. The one that matters most is **CVE-2026-111497**: an out-of-bounds write in the Brotli decoder bundled with Node.js. Malformed compressed input can crash the process, leak memory or possibly lead to remote code execution, if your app decompresses untrusted Brotli data with `node:zlib`.

Node.js rates it High, while Google scores it Critical (CVSS v4 9.2). According to Rapid7, CISA added it to its catalog of actively exploited vulnerabilities on October 27. The bug is in Google's upstream Brotli library, so it also affects Bun, Python packages, .NET, Envoy and others: patching Node alone may not be enough.

The rest of the release is a useful lesson in how fragile network validation is. Several CVEs concern TLS certificate checks fooled by unusual IP spellings (fullwidth digits, octal like `0127.0.0.1`), and a few are incomplete fixes of earlier CVEs. Another one is worth knowing for anyone shipping single executables: `crypto.randomUUID()` and `randomInt()` could repeat values in processes started from snapshots or SEAs.

## Claude: small models, open skills

On October 7 Anthropic announced **Claude Haiku 5.5**, its most capable small model to date, aimed at summarization, subagents and browser use. The announcement I read gives no pricing or context window, so I won't guess.

Why does that matter? In agentic pipelines the expensive part is rarely the one "smart" call. It's the dozens of small calls around it. A fast, capable small model makes it affordable to run many subagents in parallel.

On October 22 Anthropic made a move I find even more interesting: it donated **Agent Skills** to the Agentic AI Foundation, part of the Linux Foundation, including the name, logo and the agentskills.io domain. According to the announcement, more than seventy agent platforms already support the standard. It reminds me of what shared config formats did for the JavaScript tooling world: once a convention is no longer owned by one vendor, everyone can build on it.

Two more announcements are still unconfirmed: Claude Code Review reportedly reached general availability for Team and Enterprise, and Claude Security reportedly entered beta. Both come from a single secondary source with no link to an official announcement, so treat them as unconfirmed. On the business side, Anthropic filed an S-1 for a public listing on October 26.

## Web Platform and Tailwind: a quieter month

On the Web Platform side I found no Chrome or Firefox release notes from October that I could verify. Features like `text-justify`, `shape()`, the HTML Sanitizer API and scroll-driven CSS animations have been around since the February articles and the Chrome 146 and Firefox 149 betas, so they aren't really October news.

Tailwind CSS 4.3 appears to be out, with scrollbar styling and new colors according to the official blog feed. I haven't found a verified date or a full changelog yet. The broader trend is what I find interesting: native CSS keeps taking over jobs that used to need libraries, the same story as View Transitions and `shape()`.

## What I'd do this week

- **Running Next.js?** Upgrade to 16.4.1 or 15.5.28 today, check that `sharp` is at least 0.35.5, and delete old public previews.
- **TypeScript in a large project?** Try 7.0 on a branch, measure your build times, and keep the 6.0 alias ready for tools that haven't caught up.
- **Running Node in production?** Move to 22.23.4, 24.22.1 or 26.12.1 now (the Brotli bug is being exploited), check other runtimes that bundle Brotli, and start planning around the new yearly LTS cadence.
- **Building agents with Claude?** Haiku 5.5 is a strong candidate for cheap subagents, and Agent Skills, now under an open foundation, is a safe format to adopt if you don't want to be tied to a single platform.

The common thread is easy to see: compilers getting faster, standards opening up, and models small enough to use everywhere. Most of these changes won't make headlines on their own, but they all change how we'll work in 2027.
